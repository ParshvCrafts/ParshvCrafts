## About

I build systems that turn messy data into decisions - and increasingly, into agents that act on them.

I'm a Data Science major at **UC Berkeley** (College of Computing, Data Science, and Society), holding a **4.00 GPA** with **Dean's List** honors in every graded term. This past summer I was a **Software Engineer Intern at Amazon** on the Classification and Policy Platforms team in Seattle, where I redesigned configuration resolution for a batch ML inference platform and shipped it to production without a single incident.

My work sits where **data engineering, machine learning, and agentic AI** meet: hybrid retrieval systems over tens of thousands of products, multi-agent LangGraph workflows running as a paid SaaS, ETL pipelines over 15M+ records, and fine-tuned transformers served behind production APIs. I care most about the unglamorous parts - schema design, failover paths, evaluation, and the tests that let you ship on a Friday.

Outside the code, I'm an **AI4ALL Ignite Fellow** and **MLT Ascend Scholar**, and I've written two papers on algorithmic bias and fairness in automated decision-making.

> **Open to:** Summer 2027 internships in Data Science / Data Engineering / Machine Learning / AI &amp; Agentic Engineering - and to collaborating on open-source AI tooling.

## Featured Projects

<details open>
<summary><b>&nbsp;Interlace &mdash; Multimodal Fashion Search Engine</b> &nbsp;&middot;&nbsp; <i>ML &middot; Information Retrieval &middot; Full-Stack</i></summary>

<br/>

Semantic search across **29,000+ ASOS products** that accepts text, image, or blended cross-modal queries. Domain-adapted FashionCLIP embeddings feed two FAISS ANN indexes, fused with BM25 lexical retrieval through Reciprocal Rank Fusion - so "something like this jacket but in linen" resolves against both pixels and prose.

| | |
| :--- | :--- |
| **Stack** | Python &middot; FashionCLIP &middot; FAISS &middot; BM25 &middot; FastAPI &middot; Next.js 15 &middot; TypeScript &middot; Docker |
| **Scale** | 29,000+ products &middot; dual ANN indexes &middot; text / image / cross-modal retrieval |
| **Retrieval** | Reciprocal Rank Fusion over dense + sparse &middot; intent-weighted reranking |
| **NLU** | 9-step pipeline: regex intent parsing, catalog-trained spell correction, 5-template prompt ensembling |
| **Reliability** | Progressive filter relaxation guarantees non-empty result sets |
| **Deployed** | HuggingFace Spaces (inference) + Vercel (frontend) |
| **Links** | [Repository](https://github.com/ParshvCrafts/Multimodal_Search_Engine) &middot; [Live Demo](https://interlace-fashion.vercel.app/) &middot; [Video](https://www.youtube.com/watch?v=1bLxOZ0QqVs) |

The hard problem here wasn't embedding quality - it was that real shoppers write queries no single retrieval strategy handles well. Dense vectors miss exact brand and size tokens; BM25 misses visual intent entirely. Fusing both and reranking on parsed intent is what made results usable rather than merely relevant.

</details>

A monetized AI travel platform where a **6-agent LangGraph workflow** researches, drafts, critiques, and finalizes personalized itineraries. | | |

| **Architecture** | 6-agent LangGraph state machine &middot; multi-provider LLM routing across 10 keys |
| **Availability** | Health-scored automatic failover &middot; 99.9% uptime |
| **Monetization** | Stripe Free/Pro tiers &middot; real-time usage tracking &middot; webhooks &middot; automated quota enforcement |
| **Security** | Google OAuth &middot; JWT &middot; CSRF tokens &middot; rate limiting |
| **Performance** | Lighthouse-optimized PWA scoring 95+ |
| **Links** | [Repository](https://github.com/ParshvCrafts/AtlasMind-AI-Trip-Planner) &middot; [Live Demo](https://atlasmind-ai-trip-planner.vercel.app/) &middot; [Video](https://youtu.be/WWb9e_y1B40) |

Agent demos are easy; agent *products* are not. Most of the engineering went into the parts users never see - quota enforcement that survives webhook replays, a routing layer that degrades instead of failing, and a graph topology where a bad generation is caught by a critic node rather than by a customer.

</details>

| **Stack** | Python &middot; PyTorch &middot; FLAN-T5 &middot; FastAPI &middot; Groq &middot; React &middot; Vite &middot; Tailwind &middot; Framer Motion |

| **Quality** | **ROUGE-1 = 43.53** |
| **Performance** | Sub-second inference via Groq &middot; 60 fps frontend |
| **Testing** | 35 test cases &middot; 100% pass rate |
| **Links** | [Repository](https://github.com/ParshvCrafts/Text-Summarizer) &middot; [Live Demo](https://text-summarizer-lilac.vercel.app/) &middot; [Video](https://youtu.be/RNVwHcDpYfc) |

Writing the training loop by hand instead of reaching for a `Trainer` abstraction was deliberate: checkpoint resumption and profile switching are exactly the things that break when you can't see the loop, and they're what let the model train on interruptible free compute.
